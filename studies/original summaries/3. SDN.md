
- SDN (Software-Defined Networking) é um modelo de arquitetura de rede que adiciona uma camada de abstração para dispositivos que executam funções de rede (switches, routers, hypervisors, e mais), para gerenciá-los globalmente e de forma coerente.

- O SDN tem uma arquitetura definida da seguinte forma:
	![SDN Architecture.png](../images/SDN%20Architecture.png)

	- É um modelo semelhante ao SO, sendo responsável por atuar como middleman, gerenciando os acessos do software ao hardware. Em SDN, o Network Operating System é o responsável por prover uma interface programável para as aplicações (nível North) e também uma interface com os dispositivos de rede para programar o Data Plane (nível South)
	- No modelo de SDN, o SDN Controller é a camada que centraliza as decisões de como a rede irá se comportar e que possui uma visão global de toda a rede. 

- Pensando em distribuição baseada na imagem acima, temos:
	1. **North**: Parte mais lógica, programável e alto nível
	2. **SDN Controller**: Faz a integração entre North e South. OVN.
	3. **South**: Parte mais física, baixo nível (flows, flow tables, actions). O OVSDB e o OpenFlow são protocolos comuns que atuam via interface Southbound, já que um atua sob o gerenciamento e configuração da rede, e outro sobre o fluxo de pacotes. 


- O SDN controller tipicamente vai executar os seguintes serviços:
	1. **Topology Service** - Determina como os dispositivos de rede se conectam entre si, utilizado para construir uma topologia baseado em protocolos de discovery (LLDP).
	2. **Inventory Service** - É usado para fazer um track de todos os dispositivos de rede e armazenar informações sobre os mesmos (versão do OpenFlow suportada, por exemplo).
	3. **Statistics Service** - Pode ser empregado para ler as informações das portas
	4. **Host Tracking** - Utilizado para descobrir onde os endereços IPs e como MAC address estão localizados na rede (importante ao manipular e migrar VMs).

- Uma rede pode ser segmentada em dois conceitos:
	- **Underlay**: Infraestrutura física de rede e tudo conectado
	- **Overlay**: Abstração lógica criada sobre o Underlay usada para conectividade entre workloads. Faz essa troca de informações normalmente utilizando encapsulamento para os pacotes (GENVE, VXLAN). Essa abordagem de encapsulamento chama-se **tunneling**.

- Sobre essa questão de encapsulamento e identificação da rede virtual para transmissão de pacotes, cada uma possui um **VNI** (Virtual Network Identifier). GENEVE e VXLAN possuem até 16 milhões de VNIs.
	- Um ponto importante é que esses encapsulamentos adicionam uma camada de overhead:
		- VXLAN - 50 bytes
		- GENEVE - 58 bytes
	 Portanto as interfaces de rede devem considerar esses valores, para que o MTU não exceda o valor definido.
